# upstream

Build tool and source for *Upstream: Coffee from the cup back to the roaster*, a static, script-optional textbook for very old and low-powered machines.

## Build

The program is the build tool; the book is the folder it writes.

```sh
cargo build --release
./target/release/upstream        # finds ./content, builds into ./dist, prints the path to index.html
```

On Windows you can double-click `target\release\upstream.exe`: it looks for `content` in the
current folder, next to the exe, and up to four folders above it, builds the book into `dist`
beside `content`, prints where `index.html` is, and waits for Enter. Open that `index.html` in a browser.

Other commands:

```sh
upstream build [content-dir] [out-dir]   # explicit folders
upstream release [content-dir] [out-dir] # build, then EPUB, PDF and web zip into ./release
upstream build --buyer "A. Reader"       # print a licensee line in every page (also for release)
upstream lint  [content-dir]             # prose lint only
upstream widgets                         # list calculator kinds
upstream help
./check.sh                               # everything, including JS and DOM tests
node tests/perf/perf.js dist --report perf.md   # performance against budgets (needs Playwright)
```

The build exits with status 1 if any check fails, but still writes the book so you can look at it.
`dist/` is the product. Zip it and sell it; buyers double-click `index.html`.

## Editions

`upstream build` writes the web book, which includes `flashcards.txt`: every defined term
(with its glossary definition, or the sentence that defines it) and every self-check
question, tab-separated with Anki's header lines, so Anki imports it with no settings.

`upstream release` also writes, to `release/` beside the book folder:

- `upstream-<version>.epub`: EPUB 3 with an EPUB 2 table of contents for older readers.
  Calculators are shown as their formula and starting values, since e-readers do not run
  them. Validated with EPUBCheck 5.1 (no errors or warnings).
- `upstream-<version>.pdf`: 7 x 10 in pages typeset by WeasyPrint from one generated
  document, with running heads, page numbers, a contents page, solutions, glossary and an
  index of terms with page numbers. Skipped with a note if `weasyprint` is not on the PATH.
- `upstream-<version>-web.zip`: the web book folder, ready to sell.

With `--buyer "Name"`, every page footer, the EPUB rights statement and the PDF title page
say "Licensed to Name for personal use". Build one copy per sale. Set
`SOURCE_DATE_EPOCH` for byte-identical rebuilds of the EPUB.

The version in `book.toml` appears in every footer, linked to `changes.html`, which is
rendered from `content/changes.md` (release notes and errata).

## Dark mode

`dark.css` is linked with `media="screen and (prefers-color-scheme: dark)"`, and its rules
sit inside the same media query. Browsers that predate the query ignore the file, so old
machines and printing are unaffected; current browsers switch with the system setting.

## Performance

`tests/perf/perf.js` serves the book and loads every page in Chromium under four profiles:
a modern machine; a 2006-class PC (CPU slowed 20 times) on 1.5 Mbit/s DSL; the same PC on a
56k modem; and the 56k modem with the stylesheet and script already cached. It records
bytes, requests, first paint, the time calculators become usable, the longest main-thread
task, and the time each calculator and self-check takes, and fails if a budget is exceeded.
Throttling a modern CPU approximates old hardware; it does not replace a real old machine.

## Layout

```
content/
  book.toml           title, author, edition, licence holder (fill these in before release)
  glossary.toml       [[term]] entries
  license.md          rendered to license.html and copied to LICENSE.txt
  changes.md          release notes and errata, rendered to changes.html
  readme.txt          copied to README.txt with CRLF line endings
  front/*.md          unnumbered pages, sorted by file name
  chapters/*.md       numbered chapters, sorted by file name
  appendices/*.md     foundations appendices (label = "A" ...), sorted by file name
  figures/*.gif       data figures, generated by tools/figures.py (25 KB budget each)
assets/
  book.css            CSS 2.1 subset
  dark.css            dark colours, applied only when the system asks for them
  book.js             ECMAScript 3; pure calculations in UB.calc, DOM code below
src/
  domain.rs           types: Book, Chapter, Block, Quiz, Question, WidgetSpec
  parse.rs            text -> domain (pure)
  render.rs           domain -> HTML 4.01 (pure)
  widgets.rs          calculator registry
  lint.rs             prose, HTML-compatibility and glyph checks (pure)
  export.rs           EPUB, PDF source and flashcards from the rendered pages (pure)
  site.rs             file system: load content, write the book, zip files
tools/
  figures.py          regenerates every figure from formulas and published models
tests/js/
  calc.test.js        ES3 parse check, banned-API scan, calculation tests
  pages.test.js       loads every built page in jsdom and exercises every widget and quiz
```

## Chapter format

```text
+++
number = 2
label = "2A"               # optional; defaults to the number
title = "Extraction"
question = "One-sentence statement of what the chapter answers."
objectives = ["...", "..."]
prerequisites = ["Appendix A", "..."]
+++
CommonMark prose. Inline HTML is allowed for <sub>, <sup> and entities.

~~~widget extraction
mode = "filter"
~~~

~~~quiz
title = "Self-check"
[[q]]
type = "choice"            # or "numeric" with answer, tolerance, unit
prompt = "..."
options = ["...", "..."]
answer = 1                 # zero-based
explain = "..."
~~~
```

Other blocks:

```text
~~~example Title            worked example
~~~evidence                 strength-of-evidence box (Markdown body)
~~~figure                   file, alt, caption
~~~equations                [[eq]] name, formula, note
~~~lab                      id, title, aim, safety, materials, method, columns, rows, analysis, expected
~~~problems                 [[p]] tier ("A", "B" or "C"), prompt, solution
```

Solutions go to `<chapter>-solutions.html`, linked from each problem. Citations `[n]` must match
a numbered list under `## References`; the build reports missing or unused entries.

Use ``` for code; `~~~` is reserved for the blocks above.

## Adding a calculator

1. In `src/widgets.rs`, add a unit struct implementing `Widget` (`kind`, `title`, `body`). `body` must include a `formula(...)` line so the page works without script; a unit test enforces this.
2. Add it to `REGISTRY`.
3. In `assets/book.js`, add a pure function to `UB.calc` and a renderer `UB.KINDS['your-kind'] = function (f) { ... }` that returns HTML.
4. Add a case to `tests/js/calc.test.js`. `pages.test.js` picks up the widget automatically.

## Compatibility rules the checks enforce

- HTML 4.01: no HTML5 elements, input types or `data-` attributes (`lint::compat`).
- WGL4 glyphs only, so Windows XP core fonts render every character (`lint::glyphs`). Use `<sub>` for subscripts, never Unicode subscript digits.
- ES3 syntax (acorn, `ecmaVersion: 3`) and no post-2006 DOM APIs (`calc.test.js`).
- Size budgets: 96 KB per page of HTML, 1.5 MB for `print.html`, 3 MB per site, 25 KB per figure (`site.rs`).
- Prose rules from published catalogues of machine-writing tells (`lint::prose`).
